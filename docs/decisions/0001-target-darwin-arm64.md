# 0001 首版目标平台改为 darwin/arm64

## 背景

计划最初把首个目标定为 Windows amd64，示例命令使用 PowerShell 与 `.exe`。实际开发机是 Mac mini（Mac16,10，Apple M4，24 GB 内存，macOS 26.6.2，arm64），没有 Wine，也没有可用的 Windows 环境。交叉编译能产出 PE 文件，但节点 01 要求「反汇编与运行证据同时成立」，没有 Windows 运行环境时无法取得运行结果。

## 选项

1. 双目标：本机验证 `darwin/arm64`，同时把 `windows/amd64` 作为交付目标锁定并交叉编译。
2. 严格 `windows/amd64`：只准备 Windows 目标，运行证据等 Windows 环境，届时记为 blocked。
3. 单目标 `darwin/arm64`：首版只承诺本机平台，Windows 后移。

## 决定

选择 3。首版目标为 `darwin/arm64`，`windows/amd64` 记入 `deferredTargets`，不提供准备或构建命令。

理由是本轮交付物是编译器，验收依赖「生成的原生程序真的运行出结果」。开发与验收都在同一台 Mac mini 上进行，把目标限定在能实际执行的平台上，01.07、04.06、06.06 的运行证据才能在同一台机器上取得，不必为平台等待外部环境。双目标会让工具链锁文件、bridge 构建参数和测试矩阵在第一天就分叉，而首版还没有值得这样付出的跨平台收益。

## 影响

- `SPEC.md` 的首个目标、`PLAN.md` 的输入与目标、06.06 的运行环境、`docs/stages.json` 的 `target` 字段同步改为 `darwin/arm64`。
- 命令示例由 PowerShell 改为 zsh，产物去掉 `.exe` 后缀。
- 路径规则仍要处理大小写冲突：APFS 默认大小写不敏感，同名不同大小写的文件同样会互相覆盖，05.01 的检查不因换平台而取消。
- 宿主 Go 版本、源码提交、归档校验和与许可证由 `tools/toolchain/go.lock.json` 固定，与平台选择分开记录。

## 代价与风险

- 首版产物不能在 Windows 上运行，跨平台能力属于后续工作。
- 现有归档和旧文档仍描述 Windows 环境，它们保持原样，不作为当前实现证据。

## 复评条件

需要交付 Windows 产物时，另立节点处理交叉编译、链接器行为与独立环境验证，不在 01—06 中临时追加。若开发机更换为 Windows，本决定需要重新评估，而不是直接沿用。
