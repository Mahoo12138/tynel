# 命令行参考

本页说明 `tynel` 当前提供的命令、退出状态，以及命令行与外部工具的分工。`build`、`check`、`run` 尚未实现，用户命令集合在 06.01 固定；现在只有身份查询和工具链检查。

## 构建与运行

```zsh
# 在项目根目录构建开发用入口；需要 01.01 准备的隔离 Go。
./tools/build
# 生成 bin/tynel，并把当前提交号注入版本输出。

./bin/tynel version
```

`bin/` 不进入版本库，换一份工作副本要重新构建。构建脚本使用 `.work/toolchain` 下的隔离 Go，不使用宿主安装。

## 命令

| 命令 | 作用 | 成功输出 |
| --- | --- | --- |
| `tynel version` | 显示程序版本、编译时提交、目标平台、锁定的 Go 身份和准备状态 | 多行身份信息，退出 0 |
| `tynel help` | 输出总体用法和退出状态表 | 用法文本，退出 0 |
| `tynel help <命令>` | 输出单个命令的说明 | 该命令说明，退出 0 |
| `tynel toolchain` | 读取准备报告，列出 SDK 目录和 `go`、`compile`、`link`、`asm` 的实际路径，并确认每个工具都能解析 | 路径清单，退出 0 |
| `tynel toolchain which <名>` | 只解析一个工具，输出绝对路径 | 一行路径，退出 0 |

`toolchain` 与 `toolchain which` 是开发命令，不属于面向使用者的命令集合。它们只读准备报告，不修改工具链；准备动作仍由 `./tools/toolchain/prep` 完成。

## 退出状态

| 状态 | 类别 | 典型原因 |
| --- | --- | --- |
| 0 | 成功 | 命令完成 |
| 1 | 源码错误 | 语法、类型、未定义名称（尚未实现） |
| 2 | 用法错误 | 未知命令、缺少参数、多余的参数、未知帮助主题、未知工具名 |
| 3 | 能力限制 | 写法合法但当前原生后端不支持（尚未实现） |
| 4 | 环境缺失 | 不在项目目录内、锁文件或准备报告缺失、报告中的工具不可用 |
| 5 | 内部故障 | 编译器自身或它调用的外部进程失败 |

退出状态只由 `compiler/diagnostic` 的类别决定，命令实现不各自约定数字。四类失败分开，是为了让「工具没装好」不被读成「用户代码有错」。外部进程以非零状态退出时，诊断类别是内部故障，并保留该进程的 stderr 作为原因。

## 命令行与外部工具的职责

命令行负责三件事：解析参数、选择诊断类别、把结果写到标准输出或标准错误。它不解析 Go 的内部数据结构，也不自己生成机器码。

外部工具通过 `internal/toolchain` 的 `Runner` 接口调用：

- `LookPath` 解析工具路径；
- `Run` 启动工具并收集标准输出、标准错误和退出状态，非零退出作为数据返回，只有无法启动才算调用失败。

真实实现用操作系统进程；测试用固定工具表替换它，因此错误路径不依赖本机是否真的安装了某个工具。工具路径来自 01.01 写出的 `.work/toolchain/toolchain.json`，本包不重复推导目录命名。

## 身份从哪里来

`version` 的 Go 版本、源码提交和许可证来自 `tools/toolchain/go.lock.json`，准备状态来自 `.work/toolchain/toolchain.json`。程序不内置第二份常量，避免与准备入口记录的版本不一致。

不在项目目录内运行时，`version` 仍输出程序版本，但把目标平台标为未知并以 0 退出；`toolchain` 无法定位报告，按环境缺失以 4 退出。

## 尚未提供

`tynel build`、`tynel check`、`tynel run`、`dump facts`、`dump nir`、`build-ir` 都还没有实现。现在调用 `build` 会得到「未知命令」并以 2 退出，而不是一个看似可用却什么都不做的空壳。
