# 状态与控制组合

04.06 不新增规则，只把已经实现的赋值、循环、递归、短路、三元式和提前返回放进同一个程序，观察它们共存时是否互相干扰。

| 组合 | 输入 | 观察 |
| --- | --- | --- |
| 循环累加 | `sumTo(0)`、`sumTo(1)`、`sumTo(10)` | `0`、`1`、`55` |
| 迭代阶乘 | `factIter(6)`、`factIter(7)` | `720`、`5040` |
| 递归阶乘 | `factRec(6)`、`factRec(7)` | `720`、`5040` |
| 分支赋值 | `pick(true)`、`pick(false)` | `2`、`3` |
| 循环内提前返回 | `early(5)`、`early(1)` | `3`、`0` |
| 短路与三元式 | `score(4, true)`、`score(4, false)` | `15`、`6` |

这些结果说明：赋值仍然先算右值再写回，`while` 仍然每轮重新检查条件，`return` 仍然退出整个函数，分支里没走到的赋值不会发生，短路和三元式仍然只求值被选中的一侧；`early(5)` 在 `i === 2` 时返回时 `total` 已经累加到 `3`，`early(1)` 的循环只执行一次后返回 `0`，`score` 的 `bonus && i === 1 ? 10 : i` 在 `bonus` 为假时由短路直接给出 `false`，三元式选 `i`。破坏组合的负向用例仍然落在已有检查上：`combo-bad-return.ts` 只有循环体里的 `return`，报 `TS2366`；`combo-bad-assign.ts` 把 `number` 写成 `boolean`，报 `TS2322`；循环目标被破坏由 NIR 的 `break` 目标测试覆盖，没有为了组合放宽任何一条检查。

验收记录见[04.06 验收记录](../validation/04-06-combinations.md)。
