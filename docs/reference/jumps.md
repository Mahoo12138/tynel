# 循环跳转

`break` 和 `continue` 都作用于最近的循环。`return` 不属于循环，它退出整个函数。这张图只画内外两层：

```text
┌─ while id 1 ───────────────────────────┐
│  ┌─ while id 2 ─────────────────────┐  │
│  │  break    ───────────────────────┼──┼──▶ 退出 id 2，回到 id 1 的循环体
│  │  continue ───────────────────────┼──┼──▶ 回到 id 2 的条件检查
│  │  return   ───────────────────────┼──┼──▶ 退出整个函数
│  └──────────────────────────────────┘  │
│  循环体继续执行                          │
└────────────────────────────────────────┘
```

## 循环身份

每个 `while` 在 NIR 里有一个正整数 `id`，`break` / `continue` 带 `target` 指向它：

```json
{ "op": "while", "id": 2, "cond": {...},
  "body": [
    { "op": "break", "target": 2 }
  ] }
```

降低器维护一个循环栈，进入 `while` 时压入 id，退出时弹出；`break` / `continue` 取栈顶作为目标。验证器重新检查这条规则：目标必须等于当前最内层循环的 id，循环外的跳转和指向外层的 id 都报 `nir.loop-target`。这样即使手写 NIR，也不能跳进别的函数或已经结束的作用域。

## 三种跳转的区别

| 语句 | 目标 | 是否重新检查条件 |
| --- | --- | --- |
| `break` | 最近循环之后 | 不检查，直接退出该循环 |
| `continue` | 最近循环的条件检查 | 检查，条件为真才进入下一轮 |
| `return` | 整个函数 | 不检查，函数结束 |

`continue` 不是“跳到循环体末尾再判断”，而是回到条件本身。条件里的准备语句（短路、三元式、带打印的调用）会重新执行，这一点在 `while-cond.ts` 里用打印次数固定下来。

## 无标签与标签

本阶段只支持无标签写法。`break outer;` 这类带标签的跳转在 TypeScript 里合法，但会绕过“最近循环”的简单规则，能力检查按 `cap.labeled-jump` 拒绝。循环外的 `break` / `continue` 由 TypeScript 先报 `TS1107`；即使绕过源码检查，NIR 验证器也会拒绝。
