# 声明身份与可变存储

上一章的程序只能读声明，不能改声明。`pick` 里的 `n` 和局部 `const` 一旦绑定，值就固定了。这一节先把“名字指向哪个声明”和“这个声明的值能不能变”分开，为下一步的赋值和 `while` 做准备。

## 两次读取之间需要一次写入

看一个还不允许写入、但已经能说明问题的例子：

```typescript
function outer(): number {
  let x: number = 1;
  if (true) {
    let x: number = 2;
    console.log(x);
  }
  return x;
}
```

输出是 `2`、`1`。两个 `x` 名字相同，但它们是两个声明：外层 `x` 在函数体里，内层 `x` 在 `if` 的块里。内层声明遮蔽外层，退出块后外层仍然可读。要正确生成这段程序，编译器必须回答两个问题：

1. `console.log(x)` 里的 `x` 指向哪个声明？
2. 这个声明的值在运行时放在哪里，能不能被后来的写入改变？

第一个问题靠声明 ID。第二个问题靠可变性。两者不能混在一起：同名不等于同一个声明，同一个声明也不一定允许写入。

## 事实里的六种声明

`compiler/frontend` 现在区分这些声明种类：

| 种类 | 来源 | 可写 |
| --- | --- | --- |
| `function` | 顶层函数声明 | 不可写 |
| `parameter` | 函数参数 | 不可写 |
| `const` | 模块级 `const` | 不可写 |
| `local` | 块内 `const` | 不可写 |
| `let` | 块内 `let` | 可写 |
| `module-let` | 模块级 `let` | 可写，但本阶段拒绝 |
| `var` | `var` 声明 | 可写，但本阶段拒绝 |

每条声明还带一个 `mutable` 布尔值。它不是给人看的备注，验证器会核对它和种类是否一致：`let`、`module-let`、`var` 必须是 `true`，其余必须是 `false`。这样即使有人手写事实，也不能把 `const` 标成可写来绕过检查。

声明 ID 仍然固定。`outer` 的外层 `x` 和内层 `x` 各有一个 ID，`console.log(x)` 的引用指向内层那个，`return x` 指向外层那个。降低器的 `scope` 用 ID 做键，而不是名字；同名遮蔽因此不会把两个声明混成一个。

## NIR 里的 let 带 mutable

NIR 的 `let` 语句多了一个 `mutable` 字段：

```json
{ "op": "let", "name": "x", "mutable": true,
  "value": {"op": "number", "bits": "0x3ff0000000000000"} }
```

模块级 `const` 和块内 `const` 生成 `mutable: false`（省略），块内 `let` 生成 `mutable: true`。这个字段目前只被记录，还没有消费者；04.02 实现赋值时会用它判断目标是否可写。把它放在 `let` 上而不是另造一个 `var` 操作，是因为两者的运行时形状相同：都是“声明一个局部存储并写入初始值”，区别只在后续是否允许改写。

`mutable` 只允许出现在 `let` 上。`print`、`if`、`short`、`select` 带这个字段会被解码器拒绝，避免“看起来可写”的语句绕过验证。

## 初始化是硬要求

本阶段的局部 `let` 必须在声明处给出初始值：

```typescript
let x: number;          // 拒绝：没有初始值
let y: number = y;      // 拒绝：TypeScript 先报使用前声明
```

第一条在能力检查里报 `cap.unsupported-syntax`，因为 NIR 的 `let` 必须有 `value`；第二条在 TypeScript 里就过不去，报 `TS2448` 与 `TS2454`。为什么不让 `let x: number;` 落成 Go 的零值？因为那会把“未初始化”悄悄变成 `0`，程序看起来能跑，语义却和 TypeScript 的“使用前必须赋值”不同。这一版宁可拒绝，也不替用户补默认值。

模块级 `let` 也拒绝，报 `cap.module-let`。模块体目前只接受声明、`const` 和表达式语句；模块级可变存储会牵出初始化顺序和跨函数读写，留给后面的模块阶段。`var` 同样拒绝，局部和模块级都不在子集内。

## 作用域和存储是两层

`scope` 现在保存三样东西：参数名、局部名、局部可变性。参数和局部值分开，因为参数只在函数根作用域出现，局部值按块分层。`define` 在写入名字的同时写入 `mutable`，`isMutable` 沿父链查找。

这层信息目前只用于记录，04.02 的赋值会用它做目标检查：`const`、参数、模块常量都不可写，只有 `let` 可写。把可变性放在作用域而不是 NIR 表达式上，是因为“这个目标能不能写”是名字绑定的性质，不是某次读取的性质。

## 这一节之后

现在能做到：块内 `let` 带初始值声明，类型为 `number` 或 `boolean`，可以读取、可以遮蔽外层同名声明；`const`、参数、`let` 在事实和 NIR 里有明确的可变性标记。

04.02 在这层标记上实现了简单赋值：`x = value;` 先求值右侧，再写入可变的 `let`，`x = x + 1` 读到的是写入前的值。给 `const`、参数或模块常量赋值仍然拒绝；赋值表达式、复合赋值和自增自减也拒绝。

04.03 让 `while` 每轮重新检查条件，循环体里的写入在下一轮条件检查前生效。04.04 补上无标签 `break` / `continue`，它们只作用于最近循环，`return` 仍退出整个函数。`for` 与 `do` 尚未实现。
