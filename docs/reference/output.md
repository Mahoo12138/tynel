# 输出格式

`print` 语句在运行时调用固定支持文件里的 `tynelPrintFloat64`。它是一个受限输出：一次调用写一个 `number`，占一行。它不是 Node 的 `console`——没有格式化占位符，不接受多个参数，也不写标准错误。

本页定义这套格式，以及为什么现在这么定。

## 一行一个数

```typescript
console.log(0.1 + 0.2);
console.log(-0);
console.log(1 / 0);
```

```text
0.30000000000000004
-0
+Inf
```

每次 `console.log(<number>)` 对应标准输出的一行，行尾一个换行符。没有前缀、没有缩进、没有时间戳：输出是给程序读的，不是给人看的日志。

## 格式规则

| 值 | 输出 | 说明 |
| --- | --- | --- |
| `42` | `42` | 整数不带小数点 |
| `0.5` | `0.5` | |
| `0.1 + 0.2` | `0.30000000000000004` | 最短且可回读的十进制写法，不做四舍五入 |
| `-0` | `-0` | 负零保留符号位 |
| `NaN` | `NaN` | |
| 正无穷 | `+Inf` | |
| 负无穷 | `-Inf` | |
| `1e21` | `1e+21` | 超出定点范围时用指数写法 |

有限值用 `strconv` 的最短表示（`'g'` 格式、精度 `-1`）：这串十进制读回 binary64 会得到与原来完全相同的位模式。这正是 `0.30000000000000004` 而不是 `0.3` 的原因——`0.3` 读回来是另一个数。

四个特殊值没有「最短十进制」可言，所以各给一个固定拼写。固定是关键：同一个值在任何路径下都必须写成同一串字符，否则「输出可比较」这件事就不成立。

## 读回

有限值可以直接解析回 binary64：

```zsh
# 运行输出格式夹具，逐行看。
./bridge/tsgo/check
```

`bridge/tsgo/check` 会把五行的输出逐行解析回浮点数再按位核对：`-0` 要检查符号位而不是「等于零」，`+Inf` / `-Inf` 要检查方向，`NaN` 只能判 `isNaN`。`tests/native` 里还有一份同样的读回测试，直接跑原生产物。

读回时有两个坑：

- **负零不能用相等判断**。`-0 == 0` 为真，必须看符号位（Go 的 `math.Signbit`、Python 的 `math.copysign(1, v) < 0`）。
- **`NaN` 不等于自己**。任何 `v == NaN` 都是假，只能用 `isNaN`。

## 与 JavaScript 的差异

这套拼写是本阶段自定的，不是 `console.log` 的协议：

| 值 | Tynel 现在 | Node |
| --- | --- | --- |
| 正无穷 | `+Inf` | `Infinity` |
| 负无穷 | `-Inf` | `-Infinity` |
| 负零 | `-0` | `-0` |
| 大数 | `1e+21` | `1e+21` |

差异只出现在无穷的写法上。之所以现在不改，是因为数值语义本身还没对齐（`number` 目前就是 binary64，没有 `bigint`、没有字符串拼接、没有 `toString` 的舍入规则），单独把无穷改成 `Infinity` 只是把一个不一致换成另一个。接上完整的数值语义时（03.x）会连同输出一起定稿，到那时这份表格会被替换，而不是被悄悄修改。

## 不做什么

- 不接受多个参数：`console.log(a, b)` 报 `cap.bad-console-call`。
- 不接受字符串、布尔：字符串不在本阶段子集内，布尔输出在 03.01 加入。
- 不做格式化：没有 `%d`、`%s`，也没有模板字符串。
- 不缓冲：每次调用立即写一行，程序崩溃前已经输出的内容不会丢。
- 不写标准错误：诊断走编译器的标准错误，程序输出只走标准输出，两者不混。

## 打印器不是 console

把这套东西叫「console」容易误会。它没有 `console.error`、`console.warn`、`console.table`，也没有对象检查器；它只把一个 binary64 写成一行文本。文档里提到它时写「受限输出」或「打印器」，不写「Node console 的一个实现」。
