## 正向验收

### 输出 42，改输入得到 43

```text
$ ./bin/tynel build-ir examples/ir/add.nir.json -o out/add && ./out/add
42

$ ./bin/tynel build-ir tests/native/fixtures/add-41.nir.json -o out/add41 && ./out/add41
43
```

两份 NIR 只差一个实参的位模式（`0x4044000000000000` → `0x4044800000000000`），输出从 42 变成 43，说明结果来自实际计算而不是写死的常量。

### 特殊数值与小数

```text
$ ./bin/tynel build-ir tests/native/fixtures/specials.nir.json -o out/specials && ./out/specials
-0
NaN
+Inf
-Inf
0.30000000000000004
```

| NIR 位模式 | 值 | 输出 |
| --- | --- | --- |
| `0x8000000000000000` | 负零 | `-0` |
| `0x7ff8000000000000` | NaN | `NaN` |
| `0x7ff0000000000000` | 正无穷 | `+Inf` |
| `0xfff0000000000000` | 负无穷 | `-Inf` |
| `0x3fb999999999999a` + `0x3fc999999999999a` | 0.1 + 0.2 | `0.30000000000000004` |

负零没有被归一成正零，NaN 与无穷也没有在编译期被改写：这三类值由 `tynelNumberFromBits` 在运行时按位还原。`0.1 + 0.2` 输出 `0.30000000000000004` 而不是 `0.3`，说明二进制浮点的语义原样保留。

### 反汇编与运行证据同时成立

```text
$ go tool objdump -s '^main\.add$' out/add
TEXT main.add(SB) <autogenerated>
  <autogenerated>:1  FADDD F1, F0, F0
  <autogenerated>:1  RET
```

`FADDD` 是 AArch64 的浮点加法。`TestAddDisassemblyShowsRealArithmetic` 断言这段反汇编同时包含 `FADDD` 与 `RET`，与 42 的运行结果互为证据。

### 快照回放

`TestReplayFromSnapshotMatchesOutput` 先构建一次并读取 `.build.json` 里的 `tools.snapshot`，再用那份快照作为输入重新构建，两次输出一致。回放不依赖用户手里的原文件。

### 支持文件不被改写

`TestSupportFileIsNotRewritten` 在两次不同输入的构建前后比对 `bridge/go/support/support.go` 的字节，确认构建过程没有改动固定支持文件。

### 缓存指纹

| 产物 | 输入 sha256 前缀 | 编译器前缀 | build tag |
| --- | --- | --- | --- |
| `out/add` | `c9f89f9d0444` | `69073298` | `tynel_c9f89f9d_69073298` |
| `out/add41` | `5cd521f8df61` | `69073298` | `tynel_5cd521f8_69073298` |

输入不同、编译器相同，标签只换前一段；改完 bridge 重编后，后一段也会变。两者都参与 Go 的缓存区分。

### 编解码模糊测试

```text
$ go test -run '^$' -fuzz=FuzzDecode -fuzztime=8s ./compiler/nir
fuzz: elapsed: 9s, execs: 1063449 (0/sec), new interesting: 255 (total: 260)
PASS
```

约 106 万次输入，没有出现「解码成功但编码失败」「往返结构不一致」或「失败时返回半个模块」。模糊测试只在显式加 `-fuzz` 时运行，普通 `./tools/test` 只跑种子语料。

## 负向验收

| 场景 | 构造 | 结果 |
| --- | --- | --- |
| 损坏格式 | 截断、尾随内容、未知字段、错误位串 | `nir.malformed` / `nir.trailing` / `nir.bad-bits`，返回空模块 |
| 坏 NIR 绕过驱动 | 直接把 `bad-call.nir.json` 交给修改版编译器（不经 `build-ir` 的验证） | 编译失败：`tynel bridge: 调用不存在的函数 "missing"` |
| 被污染的输入快照 | 按哈希命名的快照文件被写入别的内容 | `环境缺失 (build.snapshot-corrupt)`，不启动构建 |
| 错误工具指纹 | 编译器二进制与戳记不符 | `环境缺失 (build.stale-compiler)`，不产出文件 |

「坏 NIR 绕过驱动」由 `./bridge/go/check` 的第三个用例覆盖：它直接调用 `go build -toolexec=...`，不经过 `internal/build` 的解码与验证，确认编译器内部的 bridge 也会拒绝。

### 零断言不算通过

`tools/test` 用 `go test -count=1 ./...` 并把没有 `ok` 行的结果判为失败；缺少修改版编译器时直接报错退出，而不是让 `tests/native` 静默跳过。

## 未覆盖

- 输出格式沿用 Go 的默认浮点格式化，不是 JavaScript `console.log` 的最终协议；无穷写作 `+Inf` 而不是 `Infinity`，这一点随 02.x 固定。
- 只验证了 `number`：没有布尔、字符串、对象和数组。
- 没有控制流，因此没有「同一路径上不同分支」的回放用例。
- 模糊测试只覆盖编解码，不覆盖 bridge 与代码生成；生成侧的错误仍靠夹具用例。
- 构建产物字节级可重复性没有断言：本记录只比较输出文本，没有要求两次构建的 sha256 相同。
