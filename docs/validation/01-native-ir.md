## 正向验收

### 输出 42

```text
$ ./out/add
42
```

### 反汇编与运行证据同时成立

```text
$ .work/toolchain/go1.27.3-sdk-darwin-arm64/bin/go tool objdump -s '^main\.add$' out/add
TEXT main.add(SB) <autogenerated>
  <autogenerated>:1  FADDD F1, F0, F0
  <autogenerated>:1  RET
```

`FADDD` 是浮点加法，`RET` 是返回。函数体只有这两条，说明结果来自运行时计算。

### 改输入得到 43

```text
$ cp examples/ir/add.nir.json out/add-41.nir.json
$ perl -pi -e 's/0x4044000000000000/0x4044800000000000/' out/add-41.nir.json
$ ./bin/tynel build-ir out/add-41.nir.json -o out/add-41
已生成 out/add-41（2429842 字节）
  输入     5cd521f8df61
  编译器   6907329847eb
$ ./out/add-41
43
```

两份描述的输入哈希不同（`c9f89f9d…` 与 `5cd521f8…`），输出从 42 变成 43。

### 数值语义

负零、NaN、正负无穷与 `0.1 + 0.2` 的用例与结果见 [01.07 验证记录](01-07-native.md)：`-0`、`NaN`、`+Inf`、`-Inf`、`0.30000000000000004`。这些值由 `tynelNumberFromBits` 在运行时按位还原，没有被编译期归一。

## 负向验收

### 坏输入在编译前被拒绝

```text
$ ./bin/tynel build-ir bridge/go/testdata/bad-call.nir.json -o out/bad
tynel: 源码错误 (nir.unknown-function): 调用了不存在的函数 "missing"
$ echo $?
1
```

`out/bad` 没有被创建。

### 失败不覆盖旧产物，也不能冒充新结果

```text
$ ./bin/tynel build-ir bridge/go/testdata/bad-call.nir.json -o out/add
（失败，退出 1）

$ ./out/add
42
$ 记录里的输入哈希： c9f89f9d0444
```

产物仍是上一次成功构建的那份，构建记录里的输入哈希也还是 `c9f89f9d…`。读者不能把这次运行当成新输入的结果——哈希没变就说明产物没变。

### 文章里的命令逐条执行

`docs/notes/01-native-ir.md` 中的命令块在本次验证中逐条执行，包括 `perl -pi -e` 的替换、`objdump` 的符号过滤和坏输入用例。最初写作时用的是 `sed -i ''`，在本机 zsh 下报错，已改为 `perl`。

## 阶段能力边界

节点 01 交付的是后端链路，不是 TypeScript 编译器：

- 输入仍是手写 NIR，`tynel build` 是未知命令。
- 没有分支、循环、局部变量、字符串和布尔；只有 `number`、直接调用、`return` 与 `print`。
- 输出格式沿用 Go 默认浮点格式化，无穷写作 `+Inf`，不是 JavaScript 的 `Infinity`。
- 修改版编译器只存在于 `.work/bridge/compile`，发行打包在 06.x。

## 未覆盖

- 没有 TypeScript 前端、tsgo 会话和声明库。
- 没有跨平台：只在 `darwin/arm64` 上验证。
- 构建产物字节级可重复性没有断言，只比较输出文本。
- 失败诊断的位置统一是 `<autogenerated>:1`，NIR 的 `pos` 还没有映射到 Go 的源码位置。
