## 验收一：void 函数恰好执行一次

`bridge/tsgo/testdata/void.ts`：

```typescript
function announce(n: number): void {
  console.log(n);
}

announce(7);
announce(8);
```

```console
$ ./bin/tynel build-ir void.nir.json -o void && ./void
7
8
$ echo $?
0
```

两次调用各输出一行：副作用没有被吞掉，也没有被重复执行。`announce` 的函数体在 NIR 里是 `print` 加一条补出来的空 `return`，`main` 里是两条 `discard` 调用。

## 验收二：表达式语句丢弃结果，不打印

`bridge/tsgo/testdata/discard.ts`：

```typescript
function add(a: number, b: number): number {
  return a + b;
}

const answer: number = add(40, 2);

answer;
add(1, 2);

console.log(answer);
```

```console
$ ./bin/tynel build-ir discard.nir.json -o discard && ./discard
42
```

只有最后一行 `console.log(answer)` 产生输出。`answer;` 求值后丢弃，`add(1, 2);` 也求值后丢弃——后者仍会执行函数体，只是结果不进输出。

## 负向验收

| 输入 | 结果 | 退出 |
| --- | --- | --- |
| `console.log(announce(1))`（void 当值） | `cap.void-value` | 3 |
| 参数名叫 `console` 的函数里调用 `console.log` | `cap.shadowed-console`、`cap.bad-type` | 3 |
| `function bad(): void { return 1; }` | TypeScript 2322 | 1 |
| `add(1)`（少一个实参） | TypeScript 2554 | 1 |

前两条是能力限制：TypeScript 接受这些代码，原生后端不支持。后两条是源码错误，前端自己就会拒绝——能力检查在源码错误面前不发言。

`cap.bad-type` 是这次补上的：`shout(console: { log(n: number): void }, n: number)` 的参数类型是对象，之前能力检查只看 `any`，会把它放过去，降低阶段再把参数一律当成 `number`。现在参数、常量、返回值都按允许的类型核对。

## 过程中发现的问题

### 裸变量名当语句会让编译器内部报错

`discard` 的第一版把表达式直接放进函数体。void 调用没问题，`answer;` 立刻炸：

```text
internal compiler error: unexpected stmt: answer
```

Go 的语法层从不允许 `x;` 这种语句，IR 层也没有对应的处理分支。改成：void 调用直接成句，`number` 表达式赋给一个从不读取的临时变量，死存储交给 SSA 清掉。细节见 [bridge 说明](../reference/bridge.md)。

### 常量算术与运行时算术不是同一个数

读回测试第一版拿 `0.1 + 0.2` 当期望值，测试失败。原因是 Go 的常量算术是精确的：常量表达式 `0.1 + 0.2` 先算出十进制 0.3，再取最近的 binary64，而运行时是两个已经舍入过的 binary64 相加，结果差一位。改成用变量相加才和程序里的行为一致。

### 输出格式从「Go 的默认格式」变成显式函数

原来直接 `fmt.Fprintln(os.Stdout, v)`，靠 `fmt` 的默认行为。现在支持文件里有 `tynelFormatNumber`，四个特殊值各有一条固定分支，有限值用 `strconv.FormatFloat(v, 'g', -1, 64)`。这样格式是本项目决定的，不是某个标准库版本的副作用。
