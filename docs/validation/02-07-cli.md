## 产物与记录的一致性

构建记录同时记下源码、NIR 与产物：

```json
"source": {"path": "bridge/tsgo/testdata/add.ts", "sha256": "1099c3c9…", "bytes": 209},
"input":  {"path": ".work/build/snapshots/f8cf27fa2458d115.nir.json", "sha256": "f8cf27fa…", "bytes": 3512},
"output": {"path": "out/add-ts", "sha256": "0ab0a419…", "bytes": 2429986}
```

用记录里的快照回放，产物逐字节相同：

```console
$ SNAP=$(python3 -c "import json;print(json.load(open('out/add-ts.build.json'))['tools']['snapshot'])")
$ ./bin/tynel build-ir "$SNAP" -o /tmp/replay
构建产物：0ab0a41927af3a4b
回放产物：0ab0a41927af3a4b
$ /tmp/replay
42
```

`source` 是项目内相对路径，换工作目录仍可读；`input` 指向按内容命名的快照，不是内存地址。记录写不进去时产物会被删除，用例 `TestRunRemovesArtifactWhenRecordFails` 覆盖这一点。

后三项由单元测试覆盖：`TestRunDoesNotExecuteAfterBuildFailure` 注入一个退出 1 的假后端，断言类别为内部故障且保留 `link: undefined reference`；`TestAnalyzeRejectsUnknownFields` 与 `TestEnsureWithoutTree` 覆盖宿主协议与源码树。

`run` 不执行旧产物：先在 `.work/run/app` 放一个打印 `STALE` 的脚本，再让 `run` 编译一份源码有错的文件：

```console
$ ./bin/tynel run bridge/tsgo/testdata/bad.ts
bad.ts:2:7: error TS2322: …
$ echo $?
1
# 输出里没有 STALE
```

`check` 不依赖后端：把 `.work/bridge/compile` 移走之后，`check` 仍退出 0，`build` 退出 4。这条同时说明「check 通过」不等于「后端工具可用」。

## 诊断与机器可读输出分流

- 诊断与宿主重建进度写标准错误，结果写标准输出。
- `check --json` 的标准错误为空；`dump` 失败时不输出 JSON。
- 构建记录的 `startedAt`、`durationMillis` 只在记录文件里，不混进 JSON 结果。

## 前端宿主的生命周期

- 首次 `check` 会构建宿主：源码变化或二进制缺失时重建，进度行写到标准错误。
- 之后同一份源码的调用不再重建，热运行约 0.08 秒。
- 源码树里的适配包副本与 `bridge/tsgo/_adapter` 不一致时直接拒绝（`host.stale-adapter`），不尝试用被改过的副本编译。
- 测试文件不参与宿主哈希：改 `_test.go` 不会触发重建。

## 过程中发现的问题

### 根模块不能导入适配包

适配包在上游模块树里，仓库根模块一旦 `require` 它，没准备前端源码的人连 `go test ./...` 都跑不起来。所以主命令行以子进程使用前端，协议放在 `compiler/pipeline`。这不是绕路，而是把「前端是外部依赖」这件事显式化：宿主二进制有戳记，协议解码拒绝未知字段，两边版本不一致会立刻失败。

### 构建记录原先只能从文件读 NIR

`build.Run` 只接受 `Input` 路径。从 TypeScript 构建时 NIR 在内存里，落一份用户可见的文件没有意义。现在加了 `InputData`：字节直接进快照，记录里的 `input.path` 指向快照本身。`source` 单独记源码身份，`input` 始终是「实际被编译的那份 NIR」。

### 记录失败会留下没有来源的产物

原来写记录失败只返回错误，产物已经发布。现在删除产物：没有记录的二进制无法复核，留着比没有更危险。

### 一条旧测试把 `build` 当成未知命令

`TestUnknownCommandIsUsageError` 原来用 `build` 当例子。`build` 成为真命令后这条会失败——改成 `frobnicate`，并补上 check、build、run、dump 的用法错误用例。
