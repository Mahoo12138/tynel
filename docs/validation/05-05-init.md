## 正向验收

夹具在 `compiler/graph/testdata/init`：`main.ts` 先导入 `b.ts`、再导入 `a.ts`，两者都依赖 `shared.ts`。

```text
$ ./bin/tynel dump init --root compiler/graph/testdata/init main.ts
{
  "order": ["…/shared.ts", "…/b.ts", "…/a.ts", "…/main.ts"],
  "prints": [
    {"module": "…/shared.ts", "value": "1"},
    {"module": "…/b.ts", "value": "3"},
    {"module": "…/a.ts", "value": "2"},
    {"module": "…/main.ts", "value": "4"}
  ]
}
```

对应打印顺序：

```text
1
3
2
4
```

- `shared.ts` 从两条路径到达，只执行一次，只打印一次。
- `b.ts` 在 `a.ts` 前，因为 `main.ts` 先写 `b` 的导入；顺序不是模块名字典序。
- 把 `main.ts` 的两行导入对调，`a` 会先于 `b`，打印顺序变为 `1 2 3 4`。

### 纯类型依赖不执行

`type-main.ts` 只 `import type { T } from "./types.ts"`；`types.ts` 里有 `console.log(9)`。

```text
$ ./bin/tynel dump init --root compiler/graph/testdata/init type-main.ts
{
  "order": ["…/type-main.ts"],
  "typeEdges": [{"from": "…/type-main.ts", "to": "…/types.ts", "typeOnly": true}],
  "prints": [{"module": "…/type-main.ts", "value": "5"}]
}
```

`types.ts` 不进入执行顺序，`9` 不会打印；类型边仍保留，检查阶段仍会读取它。

依赖图本身已经拒绝所有环；初始化计划再按值边检查一次，类型环和值环不会被混为一谈。

## 顶层 const 的存储与读取规则

- 每个进入 `order` 的模块执行一次初始化。
- 顶层 `const` 在所属模块初始化时求值并写入该模块存储。
- 导入的顶层 `const` 通过 `(Module, ID)` 读取目标存储，不复制值。
- 函数读取模块级 `const` 仍报 `module.captured-variable`；本轮不实现闭包或隐式环境。
- 类型别名没有存储，不产生初始化动作。

05.05 只输出顺序和规则；把这些初始化语句合并进一个 NIR 入口由 05.06 完成。`prints` 只识别字面量 `console.log`，用于核对顺序，不是执行器。
